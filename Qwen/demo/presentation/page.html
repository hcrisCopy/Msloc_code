32 步、8 个 batch 样本、64 条数据，分别是什么意思？

32 步 = 32 次优化器更新。当前单卡每个微批次处理 1 条，通常累积 8 次梯度再更新一次；SFT 每轮末尾只剩 6 条时也会更新。不是每生成一个 token 就更新。

同一前缀，三种分布距离
正向 KL、反向 KL、JSD 到底差在哪？


在一个回答位置，把教师下一 token 的完整词表概率记为 T，学生记为 S。这里约定“正向”是 KL(T ∥ S)，“反向”是 KL(S ∥ T)；不能只看名字判断方向。




正向 KL
别漏掉教师认可的可能
KL(T∥S)=∑vTvlogTvSv
按教师概率加权。教师觉得某 token 很可能，学生却几乎不考虑它，就会受到较强惩罚。
常称为覆盖倾向：尽量保留教师认可的多种可能。


反向 KL
别自信地选教师不认可的内容
KL(S∥T)=∑vSvlogSvTv
按学生概率加权。学生很相信某 token，教师却认为它几乎不可能，就会受到较强惩罚。
常称为寻峰倾向：受模型能力限制时，可能集中于教师认可的部分高概率选择。


当前 OPSD · JSD，β = 0.5
双方各自与中间分布比较
M=T+S2JSD=KL(T∥M)+KL(S∥M)2
先平均两套概率得到 M，再各自与 M 比较。交换师生分布，距离不变；当前训练仍然只更新学生。
单位置、自然对数下范围为 [0, ln 2]。双方几乎不重合时仍有界，但这不保证学习一定更好。




JSD 不是“正向 KL 和反向 KL 各取一半”：它们的比较对象换成了中间分布 M。三者都衡量概率差异，不能直接告诉我们视频定位是否正确。


放到当前视频任务中，怎么理解？
在生成解释或时间数字的某个位置，教师可能认可多个下一 token。正向 KL 更在意学生有没有漏掉这些可能；反向 KL 更在意学生是否把概率压在教师不认可的 token 上；JSD 同时比较师生各自与混合分布的差距。
这只是损失的倾向，不是“正向一定多样、反向一定准确”的保证。若学生能自由表示教师分布，三者的最优点都是 S=T。数字的 token 切分以实际 tokenizer 为准，不能把一个 token 默认当成一个数字字符。
当前记录没有保存逐位置完整 logits，因此这里展示公式，不伪造这条视频的概率柱状图。上方代码可核对实际 JSD 计算；下方 GRPO 的参考 KL 是另一个用途，不能混为同一项损失。




24 GB 单卡如何降低 JSD 显存？
每块处理 32 个回答 token，仍比较整个词表。反向时重算部分中间结果；没有删掉词表概率，也没有改短视频。rollout batch=1，梯度累计后的 global batch 仍为 8。原始损失与分块损失的数值、学生梯度做过 CPU 对比。
SFT 用标准前缀；OPSD 用学生自己产生的前缀。固定教师靠额外真值信息指导学生，但最终部署只有不看 GT 的学生。

三项奖励分别是什么？
R=Rloc+0.1Rformat+0.3Rexplanation
  • 定位：real 正确 +1、误报 −1、无法解析 −0.5。fake 未正确解析为 fake 得 −1；有效区间按 IoU 与边界误差打分。
  • 格式：能解析成有效 fake / real 得 +1，否则 −1。能解析不代表解释质量高。
  • 解释：仅 fake 且定位 IoU ≥ 0.30 时，用冻结 CPU NLI 比较生成解释与标注事实：覆盖分 − 0.5 × 矛盾分。real 此项为 0。
fake 有效区间的定位奖励 = 0.25 + 0.55×IoU + 0.20×边界分 − 0.25×未匹配标记。无交集时边界分为 0、未匹配标记为 1。
查看定位奖励代码与当前样本打分真值
优势是“比同组平均好多少”
Ai=Ri−R¯sR+10−4
正优势提高对应回答的相对概率，负优势降低。四条奖励一样时优势全为 0，奖励部分没有区分方向；KL 项仍可能有梯度。
使用样本标准差（分母 G−1）。不需要额外训练 critic。奖励不需要可微；梯度从策略的 token 概率回传，不穿过 IoU、字符串解析或 NLI。


把优势变成可训练的 loss
ρi,t=exp(logpθ−logpold)L=−meanimean有效回答 t[min(ρA,clip(ρ,0.8,1.2)A)−0.02KL^]
对生成的回答重新做带梯度前向。每条回答的一个优势值用于它的所有有效回答 token；先按各回答长度平均，再平均回答。提示词与 padding 不参与回答 loss。
旧策略与参考策略不要混淆
old 用于当前更新的概率比；ref 固定在 GRPO 开始时，用来限制偏离。参考模型不是 OPSD 的特权教师。当前每组只做一次策略更新，ρ 接近 1 也不代表梯度为 0。

F1 和 IoU 怎么讲？
IoU 看区间重合：交集长度 ÷ 并集长度。普通片段分类 F1 关注 fake 判断的精确率与召回率；但论文的 F1_Det 是原视频 0.01 秒时间格上的检测 F1，F1_Loc 是多个 IoU 阈值下的片段匹配 F1 平均。不能把这 64 个抽样 proposal 的分类 F1 当作整视频论文指标。正式结论应还原到整视频，使用同一测试集与正式评测脚本。

vLLM 加快生成，Ray 把工作分给不同角色
两者可以配合，但不是两个“加速开关”，也不意味着速度自动翻两倍。


生成引擎
vLLM：让学生更快写出回答
OPSD 每轮要让学生生成，GRPO 还要对同一 proposal 生成 4 次。这些自回归生成反复计算下一 token，是可以优化的耗时环节。
vLLM 管理生成过程的缓存、请求批处理和 GPU 执行。它在本项目里替换的是 rollout 生成；JSD、奖励、反向传播、优化器更新仍由训练代码完成。
这是生成引擎的作用说明；本次只测了整体组合，没有分别测每种内部优化的贡献。vLLM 官方说明
角色调度
Ray：让多张卡分工处理一批任务
把模型放进长期驻留的 Actor：生成者、教师或参考模型、训练者各自处理任务；大张量通过 Ray 对象存储传递。
多份 Rollout 分担样本，多份 Scorer 分担打分，多份 Trainer 用 DDP 同步梯度。Ray 安排资源和调用，角色如何配合、何时同步权重，仍由 demo 自己实现。
Actor 是持有模型状态的工作进程，不是一张模型结构图。Ray Actor 官方说明


把工具放回本项目的一轮训练
切换 OPSD / GRPO，查看各角色收什么、算什么、交给谁。以下是已实现的同步流程示意，方框长度不代表实测耗时。






同步屏障Trainer 更新到 v+1 → 传输新权重 → 所有 Rollout 确认 v+1 → 下一轮生成


加速机会在哪？
vLLM：缩短生成回答这一步。Ray：同一轮里，多份生成或打分任务可以并行；GRPO 的参考前向与 CPU 奖励也可并行提交。
当前实现仍然等本轮生成结束，再打分，再更新，再同步。没有把下一轮生成与本轮更新重叠起来，也没有实现跨轮异步流水线。
为什么必须同步权重？
Trainer 已经学到了 v+1，Rollout 若仍用 v，就会继续用旧学生生成。此 demo 把版本号带在样本和打分结果上，版本不一致会报错。
固定教师与固定参考模型保持不变；只把更新后的学生传给 Rollout。权重同步保证版本一致，不保证不同引擎逐 token 采样相同。


Ray 权重同步具体检查了什么？
初次传完整有效权重；之后传可训练参数影响到的有效权重，LoRA 会合入对应层。按块核对张量校验和，全部接收后提交版本；再用固定输入比较训练端与生成端的选定 token 对数概率，误差超出容差就报错。


默认 8 卡布局 · 尚未 GPU 实测
4 Trainer + 2 Rollout + 2 Scorer
Trainer 做 DDP 数据并行；Rollout 分摊生成；Scorer 分摊教师 / 参考模型前向。GRPO 另配 CPU Reward。
当前 24 GB 单卡 · 已有实测
ms-swift 训练 + HF / vLLM 生成
当前速度结果来自这条单卡路径。Ray 多角色需同时容纳多个模型副本，不能把当前 24 GB 单卡结果写成 Ray 多卡加速结论。


单卡 GRPO 实测：快多少，多用多少显存？


同一 RTX 4090 D、起始权重、数据和训练参数，各更新 32 次；去掉前 4 步，统计后 28 步。vLLM 记录了 32 次权重同步调用。整步含监测开销；显存为设备采样峰值。生成回答的内容、长度不完全相同，这不是固定长度的纯推理压测。

同一份 OPSD checkpoint-32

vLLM 采样回答奖励 / 优势 → 梯度更新 × 32GRPO-vLLM 权重

  1. 训练时会采样。temperature=0.8、top_p=0.95；两种引擎的采样实现、随机数使用和数值计算可能不同。seed=42 不代表跨引擎生成的回答逐字相同。
  2. 回答进入了训练。回答变了，奖励、组内优势和后续梯度也可能变，最终得到的权重就可能不同。这是两条训练轨迹，不是同一权重仅换推理后端。
  3. 看最终评测。当前两份 GRPO 权重均由同一份 inspect_model.py 使用 Transformers 推理。页面中的 HF / vLLM 标签指训练生成后端。


原有对齐检查验证 64 条的输入 token、像素与时空网格一致；它没有证明完整 logits 或采样输出逐项相等。现有记录也不能把结果差异精确归因到某一个内核。vLLM 官方可复现性说明

HF、vLLM、Ray、Megatron 的关系
工具在这里负责什么当前状态
HF Transformers + ms-swift加载模型、前向、loss、反向与优化器；也能生成SFT / OPSD / GRPO 单卡结果已保存
vLLM训练时生成回答，接收最新学生权重GRPO 单卡已测；不替代优化器
Ray安排 Actor、资源、任务与对象传递同步多角色代码与 CPU 检查完成；GPU 多卡未测
Megatron大模型分布式训练，例如张量与流水线并行当前 demo 未接入
这些工具有不同职责，可以组合使用；Ray 本身不会自动把模型变成 Megatron 并行训练。

常见问题与下一步验证
每个回答都对应前面的代码、公式或实测结果。


教师为什么比学生强？是不是模型更大？
当前可以是同底座、同 SFT 初始能力，差别是教师获得真假、GT 区间和解释线索。更强是特定输入条件下的实测表现，不是保证所有前缀都正确。


给教师 GT，会不会测试泄漏？
训练教师可以使用训练标注。学生提示不含这些真值，测试时也只用学生。教师预检结果不充当测试分数。


既然有 GT，为什么不只做 SFT？
SFT 主要在标准前缀上训练；OPSD 希望覆盖学生自己走出来的前缀。是否比继续 SFT 更有效，需要相同预算的对照实验支持。


做了 OPSD，为什么还加 GRPO？
希望让学生生成多种候选，并按定位、格式和解释奖励探索更好的策略。是否有额外收益要做 SFT→GRPO、SFT→OPSD、SFT→OPSD→GRPO 的公平对照；本次短跑还没有证明整体收益。


真实片段为什么仍会被误判？
SFT 只有 fake，可能形成强烈的异常描述倾向。OPSD / GRPO 虽有 real，但本次只有 10 条、训练较短，且 real 不获解释奖励。这些是排查线索，不能当成已经证明的原因。


global batch=8，32 步就是 256 个不同样本吗？
不保证。OPSD 这次是 256 次样本使用，会重复；SFT 只有 54 条，每轮末批 6 条，按实际 epoch 进度算是 248 次样本使用。GRPO 每步 8 条回答来自 2 个 proposal、每个生成 4 次；32 步对应 64 个组、256 条回答。32 始终指参数更新次数。


merge 和继续训练有什么关系？
merge 把底座 W 与 LoRA 增量 (α/r)BA 合成完整权重，适合导出固定教师。完整权重仍可新建 LoRA 训练。当前对比路径是学生继续原 adapter，教师独立冻结。


先解释，是不是启用了模型 thinking？
没有。当前 enable_thinking=false。Explanation 是可见任务回答；原文可能带空的 think 模板标记，这不等于启用了额外思考训练。


解释奖励高，能保证解释真实可信吗？
不能。NLI 对照已有标注判断事实覆盖和矛盾，标注可能不完整，额外细节也未被逐一验证。需要结合视频检查与独立解释质量评测。


多卡 / Ray 已经证明更快了吗？
没有。当前证明的是单卡 GRPO 的两种生成后端耗时差异。多卡角色调度、DDP 正确性和吞吐要另外实测，不能把更多 GPU 的收益算成框架收益。
