TextRQ 裁判完整输入

每次请求由下面的 [system] 和 [user] 两条消息组成；标签仅用于展示。
【插入……】是运行时替换的位置。所有公共前缀均已展开，没有省略。

哪些请求会发送：
- 只评格式、区间合法且 Explanation 非空的 TP/TN；FP/FN 和无效输出不发送评分请求。
- TP/TN 均发送流畅性（01）和一致性（02–03）请求。
- TP 有对应异常 GT 参考时，再发送事实评分请求（04–05），一次返回对象、类型、细节三项分数；低 IoU 的 TP 也保留。
- TN 没有异常参考，不发送事实评分请求。TP 无法选定对应 GT 时也不发送事实评分请求。

以下仅展示预测为一句的输入。预测为三句时，提示词完全相同，只需在 Text A 处插入完整三句文本；不按句拆分评分。其他句数也使用同样模板。
GT 内容由标注和裁剪范围决定，不由预测句数决定。完整覆盖事件、非 Round4 且起止标注齐全时使用 Start/Main/End；其他情况使用 Main only。

GT 字段来源（每个阶段的全部条目都插入）：
Start ← bnd_cot_st；Main ← obj_cot；End ← bnd_cot_ed。
Subject ← obj；Category ← bnd_class；Subcategory ← bnd_sub_class。
Description ← 主体的 obj_caption，或开始/结束的 bnd_caption。
Text A 是完整预测解释，Text B 是参考描述。Main 有多条时先选最相关的一条，其余 Main 不参与评分。选中的 Main 与已有的 Start、End 一起作为三个维度的评分依据；只有 Main 时只评主体内容。
下面两个事实评分示例都完整展开 3 条 Main 标注，分别插入 obj_cot[0]、obj_cot[1]、obj_cot[2]；实际条数随标注变化。每条可以描述同一对象的不同异常，也可以描述不同对象。
已检查 train_all_1209.json、test_all_1209.json、test_all_1209_0119.json：Start 和 End 各只有 0 或 1 条；Main 最多分别为 4、3、3 条。
